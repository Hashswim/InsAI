# 규칙 사전 점검과 텍스트 폼 입력

PDF 원본은 어떤 경우에도 모델 API로 전송하지 않는다.
AI 서비스가 pypdf로 텍스트 레이어에서 필요한 항목을 추출하고, 규칙으로 충분하면 모델을 호출하지 않는다.
구현은 [precheck.py](../../back/ai-service/app/chains/precheck.py)에 있다.

## 처리 흐름

```
PDF 3종 → pypdf 텍스트 추출 → 문서 제목·필수 항목·문서 간 대조
  ├─ 모두 확인됨                 → provider "rules" 응답 (모델 호출 없음, 토큰 0)
  ├─ 세 문서 모두 텍스트 없음    → provider "rules", 전 항목 UNVERIFIABLE (모델 호출 없음)
  └─ 그 외(누락·불일치·제목 불명) → JEV_TEXT_FORM 텍스트만 모델로 전송 → J/E/V
```

`ProviderDocument`에는 PDF 바이트 필드가 없다. 모델 어댑터는 `ProviderRequest.form` 문자열만 받으므로
구조적으로 PDF를 보낼 수 없다.

## 추출 항목

| 구분 | 항목 |
|---|---|
| 공통 필수 | 환자 성명, 진료일, 의료기관 |
| 공통 선택 | 주민등록번호 앞자리, 발급일, 진료과 |
| 진단서 | 진단명, 질병분류기호 (선택: 발병일) |
| 진료확인서 | 진단명 (선택: 질병분류기호) |
| 세부내역서 | 진료비 총액, 환자부담 총액 (선택: 급여 본인부담·공단부담·전액본인부담·비급여) |
| 초진기록지 | 주호소, 현병력, 진단명, 질병분류기호 (선택: 증상 시작일·과거력·진단 상태·치료 계획) |
| 영수증 | 진료비 총액, 환자부담 총액, 납부액 (선택: 금액 구분·기납부·미수금) |

문서 간 대조: 환자 표기, 진료일, 주민등록번호 앞자리, 외래 묶음의 세부내역서·영수증 환자부담 총액.
불일치는 판정하지 않고 `server_flags`로 모델에 넘긴다.

## 개인정보

- 환자 성명은 묶음 안에서만 쓰는 가명(`환자-A`)으로 바꿔 전송한다.
- 주민등록번호는 앞 6자리만 보관·전송한다. 다른 값에 섞인 주민번호도 뒷자리를 `*******`로 가린다.
- 라벨에 해당하지 않는 줄은 전송하지 않는다.

## 한계

- OCR이 없다. 스캔·이미지 PDF(합성 데이터 포함)는 항목을 추출할 수 없어 UNVERIFIABLE이 된다.
- 라벨과 값이 같은 줄에 있어야 추출된다. 표 형식으로 값이 다른 줄에 있으면 누락으로 보고 모델로 넘긴다.
- 세부내역서의 항목별 행(단가·횟수·금액)은 추출하지 않는다.
- 규칙 판정은 라벨·값의 **존재**만 확인한다. 값의 의미·정확성, 텍스트 레이어와 화면 표시의 일치는
  검증하지 않으므로 결과는 `RULE_PRESENCE_CHECK`, `human_review: REQUIRED`로 표시한다.
