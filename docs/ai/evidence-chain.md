# 작업 21 — E 단계: 근거 수집·참조 검증 체인

## 구현과 경계

`app/jev/evidence.py`의 `EvidenceChain`을 J 다음 실행 경로에 연결했다.
입력은 검증된 의료 PDF 요청과 J의 모델 초안 ProviderResult다.
모델이 제안한 evidence를 실제 요청 문서에 연결해 검사한 후 새 ProviderResult를 반환한다.
초안·근거·항목 순서·판정·설명·사용량을 임의로 변경하지 않는다.

E의 수집원은 **기존 단일 모델 호출이 제안한 근거**다. 추가 모델 호출, OCR,
텍스트 검색, 외부 링크 조회나 새 파일 저장은 하지 않는다.
PDF 텍스트와 근거 문장의 사실 일치 또는 문서 진위를 검증한 결과가 아니다.

## 서버가 검사하는 것

- 세 문서의 종류·ID 범위를 다시 검사한다. 중복 문서 ID가 인덱스에서 덮어써지지 않게 한다.
- 실제 요청 PDF를 읽어 문서 ID별 페이지 수를 만든다. 모델이 주장한 페이지 수는 사용하지 않는다.
  PDF 자체의 유효성·용량·암호화 검사는 기존 입력 계층의 책임이다.
- 공통 엄격 파서로 초안을 다시 검증한다. page는 1 이상의 정수이며,
  evidence의 document_id가 현재 요청에 있고 page가 해당 문서의 실제 페이지 이내여야 한다.
- UNVERIFIABLE의 선택적 근거도 같은 검사를 통과해야 한다.
- 항목 내부에서 (문서 ID, 페이지, 설명)이 같은 근거가 반복되면 전체 분석을 실패 처리한다.
  설명 비교 시에만 연속 공백을 합친다. 대소문자는 구분하며 반환 설명은 바꾸지 않는다.
- 같은 페이지의 서로 다른 관찰 설명, 다른 페이지·문서의 관찰은 유지한다.
  여러 항목이 같은 근거를 사용하는 것도 허용한다. 중복 검사는 항목마다 독립적이다.
- 근거를 조용히 삭제·합치거나 빈 근거를 만들어 채우지 않는다.
  SUITABLE/NEEDS_SUPPLEMENT의 빈 근거는 기존 스키마 정책대로 거절한다.
  UNVERIFIABLE의 빈 근거는 허용하며 신뢰도 0 정책을 유지한다.

문서 간 비교에서 양쪽 인용이 들어오면 순서와 연결을 보존한다.
다만 현재 Item에는 명시적 비교 유형·대상 문서 목록이 없다. 자연어 항목명을 보고 추정해
모든 NEEDS_SUPPLEMENT에 문서 두 개를 강제하지 않는다. 선명한 공란 등 단일 문서 근거도 유효하기 때문이다.
비교 양쪽의 필수 수집이나 의미적 충분성까지 서버가 보증하는 것은 아니다.

## 실패·추적·버전

알 수 없는 문서/페이지, 중복 근거, 잘못된 초안은 고정된 ValueError로 거절한다.
PDF 참조 인덱스 생성 실패도 내부 경로·문서 데이터 없는 고정 오류로 바꾼다.
실행 계층은 HTTP 502 / INVALID_AI_RESPONSE로 반환하며, 부분 성공 결과를 저장하거나
자동 재시도·fallback하지 않는다. 실패한 모델 호출 비용의 기존 예약 정책도 유지한다.

E에서 별도 LangSmith run을 생성하지 않는다. 기존 최종 trace의 inputs/outputs는 비어 있고,
근거 설명·PDF·문서 ID는 운영 메타데이터로 보내지 않는다.
판정과 근거는 업무 결과로 Spring에 저장하는 기존 경로를 유지한다.

체인 버전은 jev-chain-v4다. 프롬프트 jev-v2 및 해시는 변경하지 않았다.
작업 21 당시 응답 구조·DB 컬럼·환경변수·실제 모델 설정은 변경하지 않았다.
현재 작업 22의 [V 체인](verification-chain.md)이 E 다음에 연결되며 verification 응답을 추가했다.
규정은 비어 있고 ON_HOLD를 유지한다.

## 검증

합성 PDF 1·2·30페이지와 제어된 모델 초안을 사용해 마지막 페이지 허용,
다른 문서의 페이지 수 재사용 차단, 알 수 없는 문서·범위 초과, 중복 근거,
선택적 빈 근거, 비교 양쪽 인용 보존, 초안 불변·복사, 사용량 보존을 검사한다.
SDK 모의 응답부터 실제 API까지 중복 근거·잘못된 페이지가 502가 되고 추가 모델 호출이
없으며 trace/로그에 원문이 없는지 확인한다.

실제 사용자 문서·실제 모델 호출·사실 일치 평가를 수행한 것은 아니다.
근거의 의미적 충분성·개인정보 최소화와 전체 문서 점검 누락률은 후속 평가·안전장치 작업이 필요하다.
