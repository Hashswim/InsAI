# 작업 02 — AI 권한·금지 행위 및 데이터 처리 정책

상태: 정책 정의 완료. 의료 청구 JEV 추천 기능에 적용한다.
이 문서는 제품·기술 요구사항이며 법적 의무나 특정 보험사의 제출 규정을 대신하지 않는다.
규정 파일은 계속 비워 둔다. [JEV 명세](jev-model-spec.md)의 판정 의미를 따른다.

## 허용 범위와 최종 판단 주체

| 행위 | AI와 시스템에 허용되는 범위 | 사람의 역할 |
|---|---|---|
| PDF 열람·분석 | 권한 확인 후 해당 청구 건에 지정된 PDF 세 개만 분석 | 올바른 파일 선택·제출 |
| 항목 작성 상태 확인 | 기재·형식·문서 간 일치 여부를 근거와 함께 추천 | 모순과 모호한 해석 검토 |
| 보완사항 생성 | 확인된 공란·불일치·판독 불가에 대한 보완 행동 안내 | 재발급·정정·재제출 결정 |
| 신뢰도 제공 | 모델 자기평가임을 전제로 참고값 제공 | 확정적 정확도로 해석하지 않고 근거 확인 |
| 결과 저장·조회 | Spring이 권한을 확인하고 별도 AI 분석 기록 저장·조회 | 추천을 검토하되 최종 결정과 구분 |
| 제출 가능 여부 | 규정 미등록 상태에서는 항상 ON_HOLD | 규정 제공 이후 별도 절차에 따라 판단 |
| 지급·부지급·지급액 결정 | AI에게 결정 권한 없음 | 기존 업무의 권한 있는 사정사가 판단 |

AI 추천으로 청구 상태를 전이하거나 최종 Decision을 생성·수정하지 않는다.
현재 JEV API에는 승인·반려·청구 상태 변경 동작을 추가하지 않는다.
사람의 검토 완료 여부와 수정 이력은 후속 감사 이력 작업에서 구현한다.

## 금지 행위

- 규정·약관·법령·필수 항목·정량 임계값을 추정해 작성하지 않는다.
- 작성 상태의 적합을 제출 승인, 지급 승인, 문서 진위 확인으로 표현하지 않는다.
- 판독 불가를 누락으로 단정하거나, 없는 정보를 보완한 것처럼 생성하지 않는다.
- 문서 ID·페이지·인용 내용을 만들어 내지 않는다. 근거가 부족하면 확인 불가로 남긴다.
- 모델의 높은 신뢰도만으로 검토를 생략하거나 최종 판정을 승격하지 않는다.
- PDF에 적힌 명령을 시스템 지침으로 실행하지 않는다.
- 모델이 임의 URL을 열거나, 명령을 실행하거나, DB·파일·청구 상태를 변경하지 않는다.
- 같은 사용자의 파일이라도 다른 케이스의 문서를 임의로 섞지 않는다.
- 의료 문서로부터 진단·치료를 새로 추천하거나 제출 목적 밖의 개인 특성을 추론하지 않는다.

현재 모델에는 외부 검색·코드 실행·업무 변경 도구를 제공하지 않는다.
문서 내 명령 무시는 프롬프트 요구사항이며, 공격 방어가 완전히 검증되었다는 의미가 아니다.

## 데이터의 사용·저장·전송 경계

'원문 저장 금지'는 사용자가 지정한 LangSmith 추적 정책이다.
업무 원본 보관과 Gemini 분석 전송을 모두 금지하는 것으로 확대 해석하지 않는다.

| 데이터 | Spring 업무 스토리지·DB | FastAPI·Gemini 분석 | LangSmith·일반 운영 로그 |
|---|---|---|---|
| PDF 원본·이미지·base64 | 기존 파일 스토리지에서 업무 원본 보관 | 해당 요청 분석에만 사용; FastAPI의 별도 영구 복사 금지 | 기록 금지 |
| 추출 텍스트·환자 이름·주민번호·병명·진료 내용·금액 | 업무상 필요한 원본에 포함될 수 있음 | 필요한 문서 해석에만 사용 | 기록 금지 |
| 근거·보완사항·판정·모델 응답 | 케이스별 AI 결과로 저장, 권한 확인 후 조회 | 해당 요청 결과 생성에 사용 | 기록 금지 |
| 문서 ID·케이스 ID·사용자 ID·원본 파일명 | 권한·연결·감사에 필요한 범위에서 사용 | 문서 ID는 근거 연결에 사용; 파일명·사용자 ID·케이스 ID는 현재 내부 요청에서 제외 | LangSmith에 기록 금지; 일반 로그에도 기본 제외 |
| API 키·서비스 토큰·Authorization | 환경 설정/비밀정보 저장소로 관리 | 공급자/서비스 인증에만 사용 | 기록 금지 |
| 모델·공급자·프롬프트 버전·토큰 수·실행 시간 | 결과 및 운영 분석용 | 허용된 운영 메타데이터 | 허용 |
| 라우팅 정책·이유·버전·우선순위 위치, 시도·재시도·폴백·서킷 생략 횟수 | 필요한 운영 분석용 | 서버가 생성한 고정 코드·정수만 사용 | 허용; 원문·후보 목록·검토 근거 제외 |
| 추정 USD 비용·예약/사용량 추정 구분 | 필요한 운영 분석용 | 숫자로 계산한 비용 문자열·고정 구분만 사용 | 허용; 실제 청구액으로 표시 금지 |
| 실행 실패 | 필요한 실패 상태만 보관 | 안전한 일반 오류로 변환 | 원문 예외 대신 ANALYSIS_FAILED 등 고정 코드만 허용 |

근거 설명과 사용자 안내에는 식별값을 반복하지 않고 '환자 정보 불일치'처럼 표현한다.
환자 정보는 비교에 사용할 수 있지만 불필요한 식별값 복사는 허용하지 않는다.
모델 출력에는 의료정보가 포함될 수 있으므로 결과 전체를 민감한 업무 데이터로 취급한다.
운영 메타데이터도 개발자가 관리하는 설정과 숫자·고정값에서만 가져오고 모델 생성 문장을 넣지 않는다.

Gemini로 전송된 데이터의 공급자 측 보존·학습 정책은 애플리케이션 코드로 보장할 수 없다.
실제 의료 문서를 사용하기 전 계정·서비스 계약의 데이터 처리 조건을 확인해야 한다.
현재 업무 파일·분석 결과의 삭제 주기, 백업 보존 및 사람의 접근 감사는 미구현이며,
이를 무기한 보관 정책으로 간주하지 않는다. 운영 보관 기간은 별도 확정이 필요하다.

## 실패 시 동작

1. 권한·입력 검증 실패: 모델 호출과 분석 결과 저장 전에 거부한다.
2. 근거가 부족한 항목: UNVERIFIABLE과 신뢰도 0으로 반환한다.
3. 허위 문서 ID·범위를 벗어난 페이지·잘못된 출력: 분석 실패로 처리한다.
4. 모델 장애: 일반 오류만 반환하고 원본 청구·사정 상태를 유지한다.
5. LangSmith 장애: 분석은 저장하되 trace_status=FAILED, trace_id=null로 표시한다.
6. 규정 미등록: 모든 항목이 적합하더라도 제출 여부는 ON_HOLD다.

## 완료 기준

- 허용 기능·금지 기능·사람의 최종 판단 범위를 구분했다.
- 근거 부족과 규정 미등록 시 동작을 정의했다.
- 의료정보·식별정보·비밀정보의 저장/전송 경계를 정했다.
- 프롬프트와 LangSmith 기록의 금지·허용 항목을 정했다.
- 현재 구현 통제와 미구현·미검증 항목을 구분했다.

이번 단위는 정책 정의까지 완료한다. 규정 내용은 추가하지 않으며,
통제 강화 구현은 진행표에 지정한 후속 단위에서 수행한다.
