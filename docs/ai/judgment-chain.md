# 작업 20 — J 단계: 항목 판정 체인

## 구현 범위

`app/chains/judgment.py`의 `JudgmentChain`을 실제 `run_workflow` 경로에 연결했다.
J는 의료 PDF의 작성 상태에 대한 **잠정 추천**을 생성한다. 제출·지급 승인이나
규정 충족 여부를 판단하지 않는다. 규정 파일은 비어 있으며 최종 응답은 계속 ON_HOLD다.

실행 흐름은 HTTP 요청 검증 → 내부 ProviderRequest → J 체인 → 기존 문서/페이지 참조 검증이다.
선택된 모델의 PDF 분석은 J에서 한 번만 호출한다. E/V를 별도 모델로 다시 호출하지 않는다.
추가 토큰 비용이나 단계별 자동 trace를 만들지 않으며 기존 실행 제한·재시도 정책을 유지한다.

## J 입력과 출력

- 입력: 이미 PDF 검증을 거친 문서 세 개와 문서 종류·ID. J 진입 시에도 세 종류가
  각각 하나인지, 문서 ID가 중복되지 않는지 확인한다. 잘못된 내부 범위는 모델 호출 전에 거절한다.
  J 자체는 PDF 파일 검증·권한 확인을 대체하지 않는다.
- 출력: 기존 ProviderResult/Findings 형식의 모델 초안. 판단·근거·신뢰도·보완사항과 사용량을
  유지하므로 Spring 응답 구조나 DB 스키마를 변경하지 않는다.
- 현재 제공자 계약은 모델이 제안한 E/V 필드도 함께 포함한다. 이 필드를 받았다는 사실이
  독립적인 E/V 검토를 마쳤다는 뜻은 아니다. 별도 E/V 검증 강화는 작업 21·22 범위다.
- J는 공통 엄격 파서로 모델 결과를 다시 검증하고 복사한다. 변형된 SDK 객체도 그대로 신뢰하지 않는다.

## 판정 정책

새 `jev-v2` 프롬프트는 문서 종류, 환자 정보 일치, 발급기관, 날짜 해석,
동일 사건·동일 의미 날짜의 비교, 진단 내용, 진료 내용, 비용 항목·수량·합계를 점검하도록 지시한다.
이는 서비스 점검 항목이며 법적 필수 항목 목록이 아니다.

| 판정 | 모델에 지시하는 조건 |
|---|---|
| SUITABLE | 관찰·판독한 범위에서 작성 상태가 확인되고 모순을 찾지 못함 |
| NEEDS_SUPPLEMENT | 선명한 인쇄 항목의 공란, 명백한 형식 오류·불일치·문서 종류 오지정이 확인됨 |
| UNVERIFIABLE | 흐림·잘림·모호함·비교 대상 부족으로 판단 근거가 부족함 |

흐린 진단 내용과 선명한 공란을 구별하며, 문서 종류 오지정과 그로 인한 내용 확인 불가도
별개 항목으로 반환하도록 했다. 발급일과 진료일을 단순 비교하거나 병원이 다르다는 이유로
오류라 단정하지 않는다. 계산 범위·단위·본인부담/공단부담/할인이 불분명하면 합계를 확정하지 않는다.
의학적 적절성·진위는 판단 범위가 아니며, 주민번호 등 식별값을 결과에 반복하지 않는다.

문서 내용은 비신뢰 데이터이며 시스템 지시를 바꾸거나 외부 링크를 조회하는 명령으로 사용하지 않는다.
[공식 OpenAI 프롬프트 지침](https://developers.openai.com/api/docs/guides/prompt-engineering)과
[비신뢰 입력 분리 지침](https://developers.openai.com/api/docs/guides/agent-builder-safety)을 참고했다.
PDF 데이터는 기존처럼 입력 메시지로만 전달하며 상위 지시 프롬프트에 삽입하지 않는다.

위 의미 구분은 모델 지시다. 서버가 PDF에서 사실을 직접 추출해 재판정하는 로직은 아니다.
모델이 모든 점검 항목을 빠짐없이 반환했는지 강제하는 고정 check_id/coverage 계약도 아직 없다.
프롬프트만으로 의미적 정확성이나 프롬프트 주입 방어를 보장하지 않는다.

## 서버가 강제하는 J 고유 조건

같은 항목명·같은 대상 문서 집합에 대해 결과가 두 개 이상이면 실패 처리한다.
항목명은 비교할 때만 연속 공백을 합치고 대소문자를 구별하지 않는다. 반환 원문은 변경하지 않는다.
대상은 evidence의 문서 ID 집합이며 순서·페이지 차이는 별도 항목으로 취급하지 않는다.
근거가 없으면 빈 집합이다. 다른 진료를 따로 다룰 때는 구분 가능한 항목명을 사용해야 한다.
같은 이름이라도 대상 문서 집합이 다르면 허용한다.

서로 모순되는 중복 결과를 신뢰도가 높다는 이유로 선택하거나 조용히 합치지 않는다.
중복·파싱 오류는 기존 HTTP 502 / INVALID_AI_RESPONSE이며 재시도·fallback하지 않는다.
J는 직접 호출되더라도 자동 LangSmith tracing을 비활성화한다. 원문을 기록하지 않는다.
토큰 사용량은 그대로 실행 계층에 반환한다.

## 버전과 검증

- 프롬프트: jev-v2. 기존 jev-v1 파일은 덮어쓰지 않고 보관한다. 활성 릴리스는 v2만 허용한다.
- 체인: jev-chain-v3. J 경계와 중복 범위 검증 추가를 구분한다.
- 새 프롬프트 해시·버전·체인 버전은 응답, LangSmith 허용 메타데이터, Spring 저장 결과에 연결된다.
- C01~C05 합성 **모델 초안**을 이용해 적합·날짜 불일치·판독 불가·공란·문서 오지정 결과의
  보존, 근거·신뢰도·보완사항, 사용량과 단일 호출을 검사한다.
- 잘못된 입력 범위의 호출 전 차단, 동일 범위의 중복/모순 거절, 다른 문서 범위 허용,
  직접 호출의 자동 trace 차단, 기존 SDK/HTTP/재시도/저장 계약도 검사한다.

C01~C05 테스트는 PDF 해석의 정답률을 측정하지 않는다. 실제 사용자 PDF·실제 모델 호출·키 설정은
사용하지 않았다. 실제 판독 정확도, 점검 범위 누락률과 의미 구분 성능은 후속 평가가 필요하다.
