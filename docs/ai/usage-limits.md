# 작업 17 — 비용·속도 제한 정책

상태: 프로세스 단위 요청·실행 제한과 선택적 추정 비용 예산 구현.
실제 모델·단가·키·.env·규정은 추가하지 않았다. 금액 제한은 기본 비활성이다.
이 구현은 공급자 청구액을 보장하는 회계 원장이나 분산 사용량 제한이 아니다.

## 기본 제한

| 변수 | 기본값 | 범위 |
|---|---|---|
| JEV_LIMITS_ENABLED | true | 요청·호출 속도 및 동시 실행 제한 |
| JEV_REQUESTS_PER_MINUTE | 30 | 인증을 통과한 분석 POST의 rolling 60초 요청 수 |
| JEV_ATTEMPTS_PER_MINUTE | 60 | 모델 실행 진입 허용 수. 재시도·폴백도 같은 창 사용 |
| JEV_MAX_CONCURRENT_REQUESTS | 2 | 분석 HTTP 요청 동시 처리 |
| JEV_MAX_CONCURRENT_CALLS | 2 | 모델 실행 동시 처리. HTTP 요청 수와 별도 제한 |
| JEV_COST_GUARD_ENABLED | false | 추정 USD 예산 예약·정산 활성화 |
| JEV_REQUEST_BUDGET_USD | 미설정 | 활성화 시 필수인 양수 요청 예산 |
| JEV_DAILY_BUDGET_USD | 미설정 | 활성화 시 필수인 양수 UTC 날짜별 예산 |
| JEV_PRICING_MAX_AGE_DAYS | 30 | 단가 검토일 허용 경과일. 미래 검토일도 거부 |

기본값은 초기 MVP용 보수적 값이며 실제 공급자 할당량이나 업무 처리량을 의미하지 않는다.
사용량 제한을 꺼도 비용 제한은 독립적으로 켤 수 있다.
비용 제한 없이 예산 값만 설정하면 실수로 적용됐다고 오인하지 않도록 시작을 거부한다.
스텁은 금액 제한을 켤 수 없지만 요청·실행 제한은 적용한다.

## 요청 수와 동시 실행

`UsageGuard`가 락으로 카운터와 예약을 보호한다. 현재 인증 주체는 Spring 내부 서비스 하나다.
사용자별 한도가 아니며 사용자·케이스 ID를 FastAPI로 추가 전송하지 않는다.

분석 POST는 서비스 인증 후, 본문 읽기 전에 요청·동시 처리 제한을 검사한다.
인증 실패는 이 할당량을 소모하지 않는다. 인증 후 잘못된 JSON·미디어 등은 요청 수에 포함한다.
health/live·health/ready·version은 이 요청 제한 대상이 아니다.
요청 ID가 잘못된 경우는 기존처럼 본문 처리 전에 400으로 거부한다.

모델 진입 제한은 실행 계층에서 검사하므로 재시도·폴백으로 우회하지 못한다.
SDK 초기화/실행 진입 실패 후에도 속도 창의 허용 횟수는 돌려주지 않는다.
동시 처리 슬롯은 예외·취소 시에도 반납하며 반납/정산은 중복 호출돼도 한 번만 적용한다.
이미 진행 중인 SDK 호출은 HTTP 취소와 별개로 계속될 수 있어 모델 슬롯을 별도로 유지한다.
본문 업로드 시간 제한·네트워크 DDoS 방어는 별도 ingress/후속 보안 작업이 필요하다.

## 단가와 토큰 상한

기존 모델 카탈로그의 각 실모델에 선택적 pricing을 추가했다.
현재 실제 모델 항목이 없으므로 단가도 채우지 않았다. 입력/출력 가격을 추정해 기본값으로 넣지 않는다.

| pricing 필드 | 요구 내용 |
|---|---|
| currency | USD만 지원 |
| input_usd_per_million | 입력 100만 토큰당 검토한 비음수 Decimal 단가 |
| output_usd_per_million | 출력 100만 토큰당 검토한 비음수 Decimal 단가 |
| reviewed_on | ISO 날짜 형식의 실제 검토일 |
| source | 공급자 문서·검토 근거. 공백·비밀값·의료 원문 금지 |

금액은 JSON에서 소수 문자열 사용을 권장한다. 미등록은 0이 아니며 명시적으로 검토한 0 단가만 허용한다.
가격은 입력 길이·캐시 쓰기·이미지/PDF·추론 토큰 등 지원 경로의 가장 높은 적용 단가를
포괄하도록 관리자가 검토해야 한다. 자동 가격 조회·할인·환율·세금·계약별 요금 계산은 하지 않는다.
검토일이 최근이라는 사실만으로 실제 공급자 가격과 일치한다고 보장하지 않는다.

활성화하려면 호출 가능한 모든 후보에 단가와 context_window_tokens가 있어야 한다.
현재 비용 예약은 16,000~10,000,000 사이의 선언된 컨텍스트만 지원한다.
JEV 출력 상한 16,000토큰과 입력 컨텍스트 전체를 사용해 보수적으로 예약한다.
컨텍스트에서 출력 토큰을 빼지 않으며 실제 PDF 입력 토큰을 임의 추정하지 않는다.
따라서 실제로는 저렴한 요청도 예약 상한 때문에 거부할 수 있다.
정확한 사전 토큰 계수 API 연동과 공급자 비용 API 대조는 아직 없다.

단가·상한 누락/만료 시 ready 503, cost_policy=UNAVAILABLE이며 주 SDK 생성 전에 구성을 거부한다.
준비 상태에는 단가·예산·검토 근거·경로를 노출하지 않는다.

## 예약과 정산

실제 시도 전에 입력 컨텍스트 × 입력 단가 + 출력 상한 × 출력 단가를 100만으로 나눠 예약한다.
Decimal로 계산하고 USD 소수 9자리에서 올림한다. 요청 예산과 UTC 날짜별 예산을 동시에 검사한다.
여러 동시 요청의 예약도 하나의 락 안에서 검사·증가하므로 같은 잔액을 중복 사용할 수 없다.

- 재시도·폴백은 요청의 동일 CostAccount와 프로세스의 같은 날짜별 예산을 사용한다.
- 모델 호출 전 SDK 구성 실패·시간 부족은 금액 예약을 취소한다.
- 호출 실패·취소·사용량 누락/부분/0 보고는 예약 전액을 유지한다. 무료 호출로 해석하지 않는다.
- 유효한 결과와 완전한 양수 입력/출력 사용량이 있으면 검토 단가 기반 추정치로 조정한다.
- 어댑터의 usage_complete 표시를 워크플로에서도 보존한다. 외부 성공 응답 스키마는 바꾸지 않는다.
- 자정 뒤 끝난 이전 호출은 원래 날짜의 원장을 정산하며 새 날짜의 예산을 잘못 환급하지 않는다.

실제 보고 토큰이 선언 상한을 넘으면 더 큰 추정치를 기록하고 해당 결과를 성공 반환하지 않는다.
이후 호출과 readiness를 503으로 차단한다. 선언을 검토·수정하고 재시작해야 하며 자정에 자동 해제하지 않는다.
이는 이미 발생한 공급자 청구를 되돌리거나 잘못된 단가/상한으로 인한 초과 청구를 방지하는 보장은 아니다.

## 오류·추적·저장

요청·호출·동시 처리·요청/일일 금액 한도 초과는 FastAPI 429/RATE_LIMITED다.
속도·동시 처리 거부에는 정수 Retry-After를 넣고 금액 한도에는 임의 대기시간을 제안하지 않는다.
Spring은 이제 내부 429를 공개 429/AI_RATE_LIMITED로 전달한다(이전 503 매핑 보완).
Spring은 현재 Retry-After 헤더를 별도로 전달하지 않는다. 본문에는 고정 안내만 노출한다.
단가 구성 오류와 검증된 상한 충돌은 503이다. 한도 거부는 재시도·폴백 대상이 아니다.

LangSmith 활성 시 기존 시도 통계에 cost_estimate_usd와 cost_accounting만 추가한다.
USAGE_ESTIMATE는 완전한 사용량 기반 추정, RESERVED_BOUND는 미확인 시도를 포함한 예약 추정이다.
금액 제한이 꺼져 있으면 비용 필드를 보내지 않는다. 최종 응답 토큰은 여전히 마지막 성공 모델의 값이다.
추정 비용에는 실패 시도의 예약분이 포함될 수 있어 최종 응답 토큰만 곱한 값과 다를 수 있다.
원문 inputs/outputs는 계속 비우며 가격 검토 근거·문서·사용자/케이스 식별자를 전송하지 않는다.
현재 비용 정보는 추적 메타데이터이며 Spring 결과 DB에 새로운 비용 컬럼을 추가하지 않았다.

## 운영 한계

모든 카운터·날짜별 추정 비용·진행 중 예약은 프로세스 메모리다.
재시작하면 초기화되고 worker/서버 간 공유하지 않는다. 여러 인스턴스의 총 지출 상한이 아니다.
사용자별 공정 할당·영구 일일 회계·분산 락·공급자별 전역 쿼터·청구서 정산은 후속 구현이 필요하다.
정상 API 실행 계층을 거치지 않는 직접 어댑터 호출과 기존 Java AI 요약·문서 구조화 경로에는
이 제한이 자동 적용되지 않는다. 이번 작업의 적용 대상은 FastAPI JEV 경로다.
청구 상한이 중요한 운영에서는 이 코드만 믿지 말고 공급자 계정의 예산/알림/조직 정책과 대조해야 한다.
동일 request_id 재전송도 새 호출로 취급하며 멱등성·중복 청구 방지는 별도 작업이다.
정책·모델·단가 파일 변경 후에는 재시작한다. 가격 정보를 실행 중 자동 교체하지 않는다.

## 검증과 참고

가짜 시계·검토 단가·모델로 rolling 창, 독립적인 동시 요청/호출 슬롯,
원자적 예산 예약, 재시도 예산 공유, 누락/0 사용량, 자정 경계, 잘못된 단가·상한 충돌을 검사한다.
HTTP 검사로 인증 선행·본문 읽기 전 429·health 예외·SDK 추론 미호출·안전한 비용 메타데이터를 확인한다.

OpenAI Docs 스킬로 [공식 토큰 계수 안내](https://developers.openai.com/api/docs/guides/token-counting)와
[공식 비용 API](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/costs)를
확인해 토큰 보고·로컬 추정·공급자 실제 비용을 구분했다. 이 API들을 실제 호출한 것은 아니다.

2026-10-20: Python 3.11·3.14 각각 305개 테스트와 Ruff·mypy(29개 소스)·포맷 검사 통과.
Spring 전체 276개 테스트 통과. 임시 로컬 HTTP 서버에서 인증·요청 제한 429 포함 스모크 테스트 통과.
Python 3.14의 기존 Google SDK DeprecationWarning 1건은 남아 있다.
실제 공급자 청구·가격·계정 할당량과 운영 환경의 분산 한도는 검증하지 않았다.
